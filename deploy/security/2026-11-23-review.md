## PostgreSQL deployment

Published image change: [signed commit 85f7057](https://github.com/ThomsCody/nestswipe/commit/85f7057693b56ec64295e067ccab04251069e676).
Remote `main` was verified using direct Git, as requested.
[Tests](https://github.com/ThomsCody/nestswipe/actions/runs/45168259317) and
[container security](https://github.com/ThomsCody/nestswipe/actions/runs/45168259137)
both passed for this commit.

```text
from: postgres:16.15-alpine@sha256:f4610795587492cd4fb887c2dc3de301b813278bb6f616992061141b5f15ac36
to:   postgres:16.16-alpine@sha256:ddc1c45d23db7f0702f5a2727e28f24cbb75746f625c8c5083a190e50cf01740
```

Local validation used disposable, network-isolated Colima containers and data:
1,000 JSONB/Unicode rows survived the old-to-new image transition with an identical
checksum; XML/XSLT, transaction rollback, `pg_stat_statements`, and dump/restore
passed. Temporary containers and volumes were removed. Production metadata checks
found only `plpgsql` and `pg_stat_statements` extensions and none of the index
types called out in the release's migration cautions.

Production deployment held the deployment lock and shared backup lock. Before
replacement, a fresh logical dump was restored successfully into an isolated
PostgreSQL 16.16 container (13 public tables), then encrypted with the existing
backup recipient. A final encrypted cold snapshot of `deploy_pgdata` was taken
after stopping PostgreSQL. The existing data volume and database settings were
preserved. Only PostgreSQL was recreated; backend, browser, Garage and Caddy
container IDs and start times remained unchanged.

The stop-to-verified-health window was **11 seconds**, from 11:49:34 to 11:49:45
UTC. Verification confirmed server version 16.16, installed `libxslt 1.1.43-r4`,
`pg_stat_statements`, database connectivity from the backend environment, healthy
containers and public API. Datadog's PostgreSQL integration subsequently completed
eight checks with zero errors, with monitoring connections on both databases.

Rollback material is protected on the production host at:

```text
/home/ubuntu/nestswipe-rollbacks/postgresql-20261123/
  database-backup.tar.gz.enc       # restore-tested logical dump and globals
  pgdata-cold.tar.gz.enc           # final stopped-volume snapshot
  postgres-16.15-image.tar.gz      # old image and its original tags
  docker-compose.prod.yml.before
```

Each archive has a SHA-256 checksum. Image validation checked the original OCI
index digest, ARM64 configuration, and all 11 layer hashes and sizes. No running
or stopped container referenced the old image; its two tags and image were then
removed without force or broad pruning. Retirement completed at 11:51:11 UTC.
Existing unrelated rollback archives and application volumes were preserved.
Use the established backup recovery procedure for encrypted data; the image
archive can be restored with `docker image load`. Restoring old vulnerable
software is a recovery measure, not the desired steady state.

## Kernel package cleanup

Fresh APT metadata and simulations confirmed the exact approved plan. Installed
Oracle kernel **6.8.0-1068.72~22.04.1** (three metapackage upgrades and six new
packages), then verified package integrity, the decompressed boot image's
Canonical signature, initramfs module inventory and GRUB configuration.
Only after those checks passed were these eight packages purged:

```text
linux-image-6.8.0-1061-oracle
linux-modules-6.8.0-1061-oracle
linux-image-6.8.0-1062-oracle
linux-modules-6.8.0-1062-oracle
linux-headers-6.8.0-1062-oracle
linux-oracle-6.8-headers-6.8.0-1062
linux-oracle-6.8-tools-6.8.0-1062
linux-tools-6.8.0-1062-oracle
```

The running 1067 kernel and its packages were retained. No 1061/1062 boot files
or GRUB entries remain. `dpkg --audit` is clean, all five remaining GRUB kernel
entries retain `lockdown=integrity`, and live integrity lockdown remains enabled.
The boot ID is unchanged: **no host reboot occurred**. Kernel 1068 is selected for
the next boot under the existing overnight reboot policy; that policy was not
modified. APT service restarts were suppressed during this operation.

Kernel package logs and before-state records are retained on the host in
`/var/lib/nestswipe-security/kernel-20261123/`.
